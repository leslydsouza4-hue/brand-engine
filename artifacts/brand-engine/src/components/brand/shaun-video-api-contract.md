# Shaun video API

Base: `/api/shaun-video` (use the app's base-path-aware API URL helper). Every endpoint requires the existing Clerk sign-in cookie. Mutations require same-origin requests. JSON errors: `{error, code}`. Assets and completed jobs follow the **shared saved-session library policy: accessible to all signed-in users, never anonymous visitors**. Session state may retain `videoId` and edits; another signed-in user can reopen and render that source. Only its original uploader can complete a pending upload; ready originals are immutable.

All times are **source-video seconds**, never output seconds. Rectangles use normalized source coordinates, 0–1. Edits: `{trimStart,trimEnd,cuts:[{start,end}],blurs:[{start,end,x,y,width,height}],words:[{text,start,end}],format:"vertical"|"horizontal",framing:"fit"|"blur-fill",captionTiming?:"word"|"segment"}`. Automatic local transcription is always word timing. When passing phrase/SRT cues through `words`, explicitly send `captionTiming:"segment"`; never split cues into fabricated word times.

Caption rendering uses Poppins Bold white text and a **filled cyan rectangle** behind the currently spoken word, not a cyan outline. Word-timed captions group at most four words / approximately 26 characters per line, breaking at sentence punctuation (`.?!`) or a gap longer than 0.7 seconds. The active highlight follows each actual source-time word interval and is absent in inter-word gaps. Segment-timed captions display the whole cue without per-word highlighting. Captions are burned into the video; trim/cut mapping happens on the server.

## Upload / import
- `GET /capabilities` → `{maxUploadBytes,maxDuration,formats,wordTimestamps:true,segmentTimestamps:false,transcriptionModel:"Xenova/whisper-tiny.en",timestampMethod:"whisper-cross-attention-dtw",transcriptionLanguage:"en",transcriptionNote}`.
- `POST /uploads` JSON `{name,size,contentType}` → `{videoId,uploadURL}`. MP4 or MOV (`video/mp4` or `video/quicktime`), max 250 MiB. PUT the original file directly to `uploadURL` with its Content-Type, then call completion.
- `POST /videos/:videoId/complete` → video metadata. Probes the actual upload; rejects missing/invalid/oversized files and videos over 10 minutes or 4096 pixels per edge. This can take several seconds.
- `POST /imports` JSON `{url}` → `202 {jobId}`. Only HTTPS `share.descript.com/view/...` public share pages are accepted. Reads the public page's embedded JSON metadata and uses its supplied original-download URL only when downloads are enabled. Descript's extensionless public download endpoint can redirect through its media remux host to the exact allowlisted media-cache bucket/object pattern; every hop is independently host/path checked and public-DNS pinned. No endpoint/signature is invented and no Descript login or disabled-download restriction is bypassed. Public MP4 fallback discovery remains supported. Inaccessible or download-disabled pages fail with explicit owner-permission/MP4-upload guidance.
- `GET /videos/:videoId` → `{videoId,name,status:"ready"|"uploading",probe?,assetUrl,createdAt}`. Probe is the render helper's native video metadata.
- `GET /videos/:videoId/asset` → authenticated original file (supports Range).
- `POST /videos/:videoId/preview` JSON `{}` → `202 {jobId}` or `200 {assetUrl}` for a cached preview. Job result is `{assetUrl}`. Returns 429 while another preview for that source is processing or worker capacity is full; the client retries after a delay.
- `GET /videos/:videoId/preview` → authenticated, Range-capable VP8/Opus WebM editing proxy (new previews: maximum 640 pixels per edge, 24 fps; existing cached previews are reused without regeneration). Source duration and normalized coordinates are preserved. Original bytes remain unchanged and all exports/transcription/frame extraction continue using the original. Existing saved sessions prepare this derivative automatically when reopened.

`maxDuration` is a number of **seconds** (600), not minutes. All HTTP job progress values are **0–1** (the renderer's internal 0–100 callback is converted by the route). Returned `assetUrl` values are same-origin `/api/shaun-video/...` paths; use them with the existing sign-in cookie, never as public/signed storage links. The current Brand Engine artifact is mounted at `/`. Asset responses accept single byte ranges (`206` with `Content-Range`; invalid ranges return `416`) for playback and use private/no-store caching. Add `?download=1` for attachment disposition.

## Automation / output
- `screenPan` / `speakerPan` inside `split` are optional `{x,y}` destination-half offsets in -1..1 (omitted means centered). Pan occurs after scaling; canvas and export clip to the half. Positions persist in session edits.
- Repeated imports reuse the same source within 15 minutes, including cached preview/layout. POST imports accepts `refresh:true` to fetch current Descript content as a new source. Identical render requests reuse completed bytes; changed edits have separate cache entries.
- New transcripts retain words with invalid/overlapping boundaries inside adjacent aligned cues and report `groupedUncertainWords`; this is grouped timing, not synthetic individual word timing. Old omitted-word transcripts need retranscription.
- Split layouts optionally store independent `screenScale` and `speakerScale` factors (0.5–2; omitted means 1). Both preview and export scale around each half's center, crop enlargement, and pad reduction. Crop boxes remain unchanged. Horizontal ignores these controls.
- `POST /videos/:videoId/layout` → `202 {jobId}` or cached `200 {split,note}`. Requires a prepared preview (429 while waiting). Analyzes three frames once, caches normalized `split:{speaker:{x,y,width,height},screen:{x,y,width,height}}`. Ambiguous/changing layouts fail with a manual-crop message. This locates panels, not identities, and is not continuous face tracking.
- Edits may contain `split`; vertical rendering requires it. Screen is contained in the top 1080×960 half, speaker covers the bottom half. Split captions default to 4% above the bottom, adjustable with `captionBottom` (0.02–0.22); horizontal composition is unchanged. Manual crops and caption position live in saved session edits. Cached detection never overrides saved crops automatically.
- `POST /videos/:videoId/transcribe` → **202 `{jobId}`**. Runs real local CPU Whisper with genuine cross-attention/DTW word alignment, not evenly spaced estimates. First use dynamically downloads public Apache-2.0 `Xenova/whisper-tiny.en` ONNX model files to `/tmp/shaun-whisper-models`; subsequent jobs reuse the model process until five minutes idle. English speech only; users should review recognition and timing. One CPU ASR at a time; 12-minute hard timeout. No audio is sent to a third-party transcription service.
- `POST /videos/:videoId/render` JSON edits above → `202 {jobId}`.
- `POST /videos/:videoId/frames` JSON `{time}` → `202 {jobId}` for a PNG still at source time.
- `GET /jobs/:jobId` → `{jobId,kind,status:"queued"|"running"|"succeeded"|"failed",progress:0..1,phase?,videoId?,error?,result?,createdAt,updatedAt}`. Show `phase` during transcription, especially first-use model download.
  - import result: video metadata.
  - render/frame result: `{assetUrl,contentType}` (protected GET URL; render MP4, frame PNG).
  - transcription result: `{text,words:[{text,start,end}],segments:[],timing:"word",timestampMethod:"whisper-cross-attention-dtw",model:"Xenova/whisper-tiny.en",language:"en",duration,omittedUncertainWords}`. All times are source seconds. Model words with invalid/out-of-source/zero-duration/overlapping timing are omitted, not assigned invented times; `omittedUncertainWords` is their count. Populate editable caption words from this result and enable normal rendering with those words. No automatic display/caption export should falsely claim human accuracy.
- `GET /jobs/:jobId/asset` → protected output, supports Range / download.

Poll job status every 1–2 seconds until terminal. Errors are terminal; display their actual message. At most two local workers and two outstanding jobs per user per server process; busy requests return 429. Metadata, originals and outputs persist in private App Storage (no schema migration). In-flight work with no durable update for 20 minutes becomes a failed job on status read; retry explicitly. Pending direct uploads expire after one hour; ready videos and outputs have no automatic expiry. Intermediate local files are removed after each task. Signed upload URLs expire after 15 minutes. Never persist signed upload URLs in saved session state.
